\section{总体实现思路}

\subsection{从大纲到可验收交付物}

建设过程没有简单堆叠课程参考材料，而是先把大纲中的三课时任务转化为学习目标，再为每个目标设计实验、代码证据和验收方法。

\subsection{三项实验的递进主线}

\begin{enumerate}
  \item \textbf{先有状态：}实验一解决“智能体如何记住、更新和隔离信息”，建立多轮对话基础。
  \item \textbf{再接工具：}实验二解决“模型如何通过明确契约访问外部数据”，强调参数校验、证据和失败处理。
  \item \textbf{最后处理多模态行动：}实验三把屏幕理解结果约束为结构化动作计划，再经过置信度、高风险确认和审计门。
  \item \textbf{汇总为课程项目：}第12课要求学生把状态、模型、工具、安全门、日志和评测组织成完整方案。
\end{enumerate}

\subsection{关键设计原则}

\begin{tabularx}{\textwidth}{L{3.2cm} Y}
\toprule
原则 & 在本次实现中的体现\\
\midrule
离线优先 & 默认使用本地JSON、SQLite和MockVLM；没有网络和密钥也可完成基础实验。\\
契约优先 & 工具输入、工具结果和多模态动作均使用结构化字段，便于校验和测试。\\
证据优先 & 车辆状态必须来自工具结果，UI动作必须引用识别证据；缺少证据时拒绝编造。\\
安全优先 & 高风险动作需要确认，所有座舱动作仅模拟执行，不直接连接真实控制接口。\\
同步交付 & 教学PPT、实验指导书、报告模板、项目模板和代码使用同一实验主线。\\
可复现 & 提供统一目录、自动测试和一键PDF构建脚本，降低环境差异。\\
\bottomrule
\end{tabularx}

\subsection{自动测试结果}

在\texttt{code/}目录执行：

\begin{lstlisting}
python -m unittest discover -s tests -v
\end{lstlisting}

当前结果为8项测试全部通过。自动测试覆盖的核心行为包括：

\begin{itemize}
  \item 记忆事实新增、事实更新、会话隔离和持久化；
  \item 车辆工具正常查询、未知车辆或异常输入的结构化失败；
  \item VLM普通动作模拟、未知动作拒绝和高风险确认。低置信度拒绝逻辑已实现，列入人工验收。
\end{itemize}

\subsection{PDF构建结果}

在课程包根目录执行：

\begin{lstlisting}
powershell -ExecutionPolicy Bypass -File .\build.ps1
\end{lstlisting}

预期所有TeX源文件连续编译两遍且命令正常结束。脚本已能够自动定位系统中的XeLaTeX，并在缺少编译器时给出明确错误。

\leadbox{状态口径：}{
“已通过”只对应当前离线基础版和已经纳入测试的行为。在线模型质量、不同供应商接口兼容性和真实座舱系统集成需要独立环境与额外测试，不能由当前结果替代。}

\subsection{二级验收：代码与功能}

\begin{enumerate}
  \item 在\texttt{code/}目录运行8项自动测试，要求全部通过。
  \item 运行实验一，分别使用两个会话编号输入不同事实；要求同会话能回忆、跨会话不串数据、重启程序后仍可恢复。
  \item 运行实验二，询问车辆电量、胎压和故障码，再输入不存在的车辆编号；要求工具选择正确，失败以结构化结果返回，不伪造数据。
  \item 运行实验三，测试普通操作、低置信度操作和高风险操作；要求普通操作仅模拟执行，低置信度被拒绝，高风险操作在确认前不执行。
\end{enumerate}

\section{当前边界与后续工作}

\begin{itemize}
  \item \textbf{在线模型：}在线文本模型和VLM只提供兼容接口适配示例，尚未为课程统一冻结厂商、模型和密钥管理方式。
  \item \textbf{MCP版本：}示例按Python SDK v1思路编写，可选依赖暂时限制为\texttt{<2}；课程环境冻结时应重新核对。
  \item \textbf{真实车辆：}当前仅面向教学模拟，不连接CAN、车机执行器或真实车辆控制接口。
  \item \textbf{公开发布：}仓库结构已经整理，但尚未代替课程组发布到GitHub，也未擅自选择开源许可证。
  \item \textbf{增量完善：}后续收到课程组新增材料时，可继续补充图示、案例和引用，但应保持三项实验主线、测试和安全边界不被破坏。
\end{itemize}

建议课程组下一步完成四项决策：确认课时长度与授课深度、冻结课堂Python和可选依赖版本、确认评分权重与提交格式、确定仓库公开范围和许可证。
