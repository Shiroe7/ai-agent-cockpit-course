\section{实验一：结合记忆系统实现多轮对话}

\subsection{实验目标}

\begin{enumerate}
  \item 理解模型调用本身通常不自动保存会话状态；
  \item 区分消息历史、会话事实和长期记忆；
  \item 使用 session ID 隔离不同会话；
  \item 使用 SQLite 保存消息与事实；
  \item 通过测试发现记忆覆盖、过期和污染问题。
\end{enumerate}

\subsection{核心结构}

基础实现位于：

\begin{itemize}
  \item \texttt{lab01\_memory\_chat/memory.py}：SQLite 存储层；
  \item \texttt{lab01\_memory\_chat/agent.py}：事实抽取、检索和回答；
  \item \texttt{lab01\_memory\_chat/cli.py}：命令行交互；
  \item \texttt{tests/test\_lab01.py}：持久化、隔离和更新测试。
\end{itemize}

本实验将记忆分成两层：

\begin{enumerate}
  \item \textbf{消息历史}：保存原始用户与智能体消息，支持回放与审计；
  \item \textbf{结构化事实}：把姓名、偏好、温度等稳定信息保存为键值，避免每次读取完整历史。
\end{enumerate}

\subsection{实验步骤}

\subsubsection{步骤1：启动会话}

\begin{lstlisting}
python -m lab01_memory_chat.cli --session student-01
\end{lstlisting}

\subsubsection{步骤2：写入并回忆信息}

依次输入：

\begin{enumerate}
  \item \texttt{我叫小刘}
  \item \texttt{我喜欢安静的座舱}
  \item \texttt{我希望座舱温度设为24度}
  \item 隔几轮后输入：\texttt{我叫什么？}
  \item 输入：\texttt{我的偏好是什么？}
\end{enumerate}

记录每一轮的回答、当前 facts 表和消息数量。

\subsubsection{步骤3：验证持久化}

输入 \texttt{exit} 退出程序，重新使用相同 session ID 启动，再次询问姓名和偏好。若仍能回答，说明数据已从 SQLite 恢复。

\subsubsection{步骤4：验证会话隔离}

\begin{lstlisting}
python -m lab01_memory_chat.cli --session student-02
\end{lstlisting}

直接询问姓名。预期结果为“当前会话中还没有记录”。若返回 student-01 的信息，则发生了跨会话泄漏。

\subsubsection{步骤5：验证事实更新}

在 student-01 中先输入“我喜欢安静的座舱”，再输入“我喜欢轻音乐”，然后询问偏好。观察 \texttt{upsert} 如何更新同一键。

\subsection{思考与拓展}

\begin{enumerate}
  \item 消息历史持续增长时，应选择截断、摘要还是检索？说明取舍。
  \item 给记忆增加 \texttt{source}、\texttt{valid\_until} 和 \texttt{verified} 字段。
  \item 设计一条“旧偏好不再适用”的测试，并实现淘汰策略。
  \item 将基础规则抽取替换为在线模型，但保留 SQLite、session ID 和测试。
\end{enumerate}

\section{实验二：设计并调用车辆数据查询工具}

\subsection{实验目标}

\begin{enumerate}
  \item 把自然语言问题转换为“工具名 + JSON 参数”；
  \item 使用 Schema 检查必填字段、类型和额外参数；
  \item 区分规划错误、参数错误、业务错误和执行错误；
  \item 使用 JSONL 保存工具调用轨迹；
  \item 了解 Function Calling 与 MCP 的层次关系。
\end{enumerate}

\midrule

\section{课程项目：选题与设计}

\subsection{选题原则}

课程项目应满足以下五项：

\begin{enumerate}
  \item 有明确用户和具体座舱场景；
  \item 至少包含记忆、工具或多模态中的两类能力；
  \item 输入、输出和状态可以结构化描述；
  \item 有失败分支、风险控制和审计日志；
  \item 能用测试用例客观验收，而不是只展示一次演示。
\end{enumerate}

\subsection{推荐选题}

\begin{itemize}
  \item 车辆状态问答与故障解释智能体；
  \item 驾驶前座舱检查助手；
  \item 车载手册检索与操作指导智能体；
  \item 多模态座舱 UI 导航助手；
  \item 行程规划与能耗解释智能体。
\end{itemize}

\subsection{技术方案最小闭环}

项目方案至少画清楚：

\begin{enumerate}
  \item 用户输入与场景状态；
  \item 模型的角色和输出契约；
  \item 可调用工具及其权限；
  \item 记忆保存、检索、更新和删除策略；
  \item 执行前校验与高风险确认；
  \item 执行结果写回和失败重规划；
  \item 日志、测试与最终输出。
\end{enumerate}

\section{常见问题}

\begin{description}
  \item[运行时找不到模块] 请确认当前目录是 \texttt{code/}，并使用 \texttt{python -m ...} 运行。
  \item[SQLite 文件被占用] 关闭仍在运行的命令行程序，不要同时让多个程序写同一实验数据库。
  \item[模型输出不是 JSON] 不要直接执行；先提取并验证 JSON，失败时要求模型重试或拒绝。
  \item[工具调用反复循环] 设置最大步骤数、超时、预算和连续失败断路器。
  \item[MCP SDK 版本变化] 基础实验先使用本地 Tool Registry；正式冻结环境时再更新可选 MCP 示例。
\end{description}
